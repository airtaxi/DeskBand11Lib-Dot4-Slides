STEP 1 · WIN32

팝업 창을 자식 창으로 바꿉니다

TaskbarContentHostBase.cs─ ▢ ✕
// 1. 창 스타일 교체: 최상위 팝업 → 자식 창
var style = GetWindowLongPtr(hwnd, GWL_STYLE);
style &= ~(WS_POPUP | WS_CAPTION | WS_THICKFRAME);
style |= WS_CHILD;
SetWindowLongPtr(hwnd, GWL_STYLE, style);

// 2. 작업표시줄의 자식으로 입양
SetParent(hwnd, taskbarHwnd);  // Shell_TrayWnd

// 3. 빈 공간에 배치하고 클리핑
SetWindowPos(hwnd, x, y, width, height, ...);
SetWindowRgn(hwnd, CreateRectRgn(0, 0, width, height), true);

창은 그대로입니다

XAML 트리도, 입력도, 렌더링도 전부 살아있는 진짜 창입니다. 스타일 비트만 바뀝니다

되돌릴 수 있습니다

Detach하면 원래 스타일과 부모를 복원해서 평범한 창으로 돌아갑니다

LIMITATIONS

한계와 배운 점

  • 여긴 문서화되지 않은 영역입니다. Windows 업데이트가 언제든 깨뜨릴 수 있습니다공식 API가 없는 곳이니 감수해야 하는 부분입니다
  • 그래서 감시와 복구를 처음부터 설계에 내장했습니다폴링 감시 · TaskbarWindowRecreated · 모니터 재연결 자동 복귀, 깨질 수 있다는 전제로 설계했습니다
  • UIA 기반 측정은 내부 구현 변화에 비교적 유연합니다AutomationId는 접근성 계약이라 픽셀 좌표 하드코딩보다 오래 살아남습니다
